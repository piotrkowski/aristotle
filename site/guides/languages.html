Add a language

Two different things: the language of the interface, and the languages of your books.

The interface

The interface is in English by default, with Polish as a translation. Settings › Language lists every language built in, each by its own name, and switching redraws the screen at once.

Every message lives in one JSON file per language, crates/aristotle-i18n/locales/<code>.json, with en.json the source of truth. Messages are grouped one level deep by screen ("library": {"title": "Library"}), with {name} placeholders, and plural messages hold their forms ({"one": "{n} book", "other": "{n} books"}). The build checks every file against en.json and embeds it, so the Kindle reads no files and a broken translation fails the build.

Adding a language

  1. Copy crates/aristotle-i18n/locales/en.json to <code>.json, named with the language's code (de.json).
  2. Translate every message and fill in "@locale": name in the language itself, decimal, the twelve months as they appear in a date, the seven weekdays from Sunday, and the date ({weekday}, {day}, {month}, {year}) and time ({h}, {hh}, {mm}) patterns. Keep every {placeholder}; plural messages need the forms the language's rule uses.
  3. If the language's plurals are not "one for 1, other otherwise", add a rule to crates/aristotle-i18n/src/plural.rs (Rule::for_language, categories, select) with tests over 0, 1, 2, 5, 12, 14, 21, 22, 25, 112 and 122. Polish, for example, has one, few and many: 1 książka, 2 książki, 5 książek.
  4. Build with cargo test -p aristotle-i18n. It names every missing key and wrong placeholder. A translation still in progress can say "complete": false in "@locale"; its missing messages then fall back to English, with a build warning.
  5. Look at every screen: aristotle-ui-preview --lang <code>, and the reader's aristotle --preview ... --lang <code>. Long words may need shorter wording in chips and segment labels.

The language then appears in the settings by itself. The details are in Adding a language in the UI framework notes.

Your books

Books are hyphenated in their own language, whatever the interface language. The default build ships patterns for Polish, English (US and UK), Ancient Greek and Latin. Others can be added at build time, by name in HYPH_LANGS (German is de-1996, French fr):

HYPH_LANGS="pl en-us en-gb grc la de-1996 fr" tools/build-render.sh device

The script pins every file it downloads, so a new language also needs the SHA-256 of its hyph-utf8 licence notice in tools/build-render.sh; it stops with a message naming the language until then. Plato loads every pattern file in the bundle the first time it hyphenates, which is why the default ships only five.

The patterns come from Plato's release, which collects them from hyph-utf8. A book's language comes from its metadata; when an EPUB declares several, Aristotle picks the one its text is actually written in.

The default build also cuts its fonts to Latin and Greek, polytonic included. FONT_SUBSET=none keeps everything the fonts have, Cyrillic among it.
