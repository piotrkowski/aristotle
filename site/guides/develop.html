Develop

Most work needs no Kindle. The host renders each screen to PNG exactly as the panel would show it.

One workspace, two build paths

Plain cargo test checks the pure-Rust default members. The renderer and reader app also belong to this workspace, but need Plato's C libraries. From the repository root:

. devloop/env.sh
export CARGO_TARGET_DIR="$ARISTOTLE_CACHE/target"
cargo test

# Build the native members' C libraries once for the host.
PLATO_TARGET=x86_64-unknown-linux-musl PLATO_LIBS_ONLY=1 tools/build-plato.sh
CARGO_CMD=test tools/build-render.sh host

Previews on the host

Two previews run the device code with simulated touches and write a PNG for each step:

# all screens of the toolkit, day and night
cargo run --release -p aristotle-ui --bin aristotle-ui-preview

# the reading interactions on a test book: menu, contents,
# dictionaries, selection, highlights, footnotes, "go to"
devloop/host/make-reading-test-epub.py BOOKS/Aristotle/proba-czytania.epub
$ARISTOTLE_CACHE/render/host/aristotle --data DATA --library LIB \
    --dict DICTIONARIES --preview OUT BOOKS/Aristotle/proba-czytania.epub

Both log each panel update with its waveform and rectangle, the reader to updates.txt. Compare the output before and after a change. Images should only differ if the change is visual.

The emulator

devloop/emulator/setup.sh builds a QEMU Paperwhite 4 with stock firmware 5.13.6, KUAL, MRPI and the jailbreak. Try anything that could hang the boot, touch the stock framework or load kernel code there first. The emulator does not reproduce e-ink timing or ghosting.

devloop/emulator/setup.sh
cd $ARISTOTLE_CACHE/emulator/eink-emulator
./eink run pw4 --headless --qmp-socket --serial-socket

Scenarios on the device

aristotle-observe plays touch scenarios from devloop/kindle/scenarios/ against the stock interface or Aristotle. From the panel driver's log it reports, for each interaction, the time to the first and last update, the update count, flashes and waveforms.

# from devloop/kindle/scenarios/aristotle-transitions.txt
label turn-fwd
tap 900 800
wait 1500
label menu-open
tap 536 60
wait 2000
/var/tmp/aristotle-observe run /var/tmp/aristotle-transitions.txt

Start each scenario from a known state with go-home and check its steps with snap screenshots. Unchecked numbers were wrong more than once. A change to what reaches the panel should keep the same updates and waveforms, and latency within 10 %.

Screenshots

tools/screenshots/compose.sh makes the screenshots for the README, the docs and this site from 1072 × 1448 framebuffer captures in $ARISTOTLE_CACHE/captures/readme/, taken with devloop/host/screenshot.sh. manifest.toml lists each output and its inputs. The outputs are framed shots and demo frames in the panel's 16 grays.

The demo reads site/demo/frames.js, which holds each frame's image, alt text and tap targets in panel pixels. For new captures or another language, replace the images and that file.

Before you send a change

  • Read AGENTS.md, which covers the framebuffer stride, the waveform numbering and the rule of one panel update at a time.
  • Run the checks in CONTRIBUTING.md.
  • Test with public-domain books or text written for the test.
  • Do not write to the root filesystem, boot partitions, /mnt/wfm or /var/local on a device without its owner's consent.
