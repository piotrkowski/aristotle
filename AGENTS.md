# AGENTS.md

Repo `aristotle` (the working name), product **Aristotle**: a replacement for the Kindle Paperwhite 4's interface, with its own Rust UI framework, a reader built on Plato's document engine, and a device agent for SSH over USB. See `README.md` for the overview, `docs/architecture.md` for the structure and `docs/pw4-reference.md` for the full device reference. This file is the short list of things you would otherwise get wrong. `.github/CONTRIBUTING.md` has the build and the checks.

## Ground rules

- Work on a real device can brick it, and **no recovery path has been verified yet**. Until one exists, do not write to the root filesystem, boot partitions, bootloader, `/mnt/wfm` or `/var/local` without the user's explicit go-ahead.
- Run device-side experiments as reversible overlays: bind mounts, `/var/tmp` copies, stopped services. A reboot must bring back the stock system.
- Everything in this repo is in English: code, comments, docs, commits.
- `third_party/plato` is our Plato fork ([piotrkowski/plato](https://github.com/piotrkowski/plato), branch `aristotle`): upstream Plato plus one commit per change. Changes to Plato go there as commits on `aristotle`, followed by a submodule bump here (`docs/reader.md`, "Plato fork"); keep each one small and described. When you borrow other code, copy it into our crates and keep the AGPL notice and attribution, and list it in `THIRD_PARTY.md`.
- Test data and docs use public-domain books (Prus, Mickiewicz, Plato in Witwicki's translation, Austen, Melville) or text written for the test, never copyrighted books or anyone's own library.
- Mark device claims with their source: verified on the device, read from firmware, or borrowed from KOReader or other projects. Don't promote an inference to a fact.

## Host environment

- Keep builds, downloads and probe output in the cache directory, `$ARISTOTLE_CACHE`, and set `CARGO_TARGET_DIR` and `TMPDIR` there: the C build and the emulator are large, and `/tmp` is a small RAM disk on many hosts. `devloop/env.sh` defines the variable (default `${XDG_CACHE_HOME:-$HOME/.cache}/aristotle`) and sets `TMPDIR`; every script sources it, and so should your shell before running cargo or `ssh -F devloop/host/ssh_config` by hand. Never write paths of your own machine into the repo; name the variable instead.
- Large artifacts live outside git. `docs/pw4-reference.md` lists them under "Host-side artifacts". Read the stock rootfs image without root using `debugfs -R 'cat /etc/...' rootfs.img`.
- RE tools: `tools/fetch-tools.sh` installs pinned Ghidra, JDK 21 and JADX. Then `. "$ARISTOTLE_CACHE/tools/env.sh"`. A Ghidra-backed MCP server, if you register one for this directory, lets coding agents decompile ARM binaries from the firmware. The Python helpers in `probe/host/` need a virtualenv at `$ARISTOTLE_CACHE/venv` (`python-lzo`, `fdt`).
- Some hosts guard against destructive commands (`rm -rf`, `mv` inside caches, truncating `>` redirects). Scripts here write fresh output directories instead of cleaning up, and append to logs with `>>`; keep it that way.
- If something on the host mounts the Kindle read-only when it is plugged in (a udev rule, a highlights exporter), remount it read-write before installing: `udisksctl unmount -b /dev/sdX && udisksctl mount -b /dev/sdX`. `install-extensions.sh` does this itself.

## Running code on the device

- **Emulator first.** `devloop/emulator/setup.sh` builds katadelos' QEMU fork and creates a stock PW4 5.13.6 instance with KUAL, MRPI and the jailbreak under `$ARISTOTLE_CACHE/emulator`. Then `./eink run pw4 --headless --qmp-socket --serial-socket` from `eink-emulator/`: SSH (`ssh -i build/ssh/id_ed25519 -p 2222 root@127.0.0.1`) is up after about 30 s and Home after about 2.5 min. The setup applies `eink-emulator-pw4.patch`, which fixes two things. First, the PW4 board id must start with `P` and carry `15R`, or the guest boots as `yoshi` and hangs. Second, under QEMU the on-screen keyboard is limited to one language, because loading a second `kb` plugin crashes (a QEMU bug, not yet located), and three crashes make the guest reboot and QEMU exit. Try anything that could hang boot, touch the framework or kexec there first. Real e-ink behaviour (ghosting, waveform timing) still needs the device. The first QEMU build takes a while.
- **Dev loop: SSH over the USB cable, no replugging.** KUAL › Aristotle USB network › Start (`devloop/kindle/aristotle-usbnet`) unloads `g_mass_storage`, loads `g_ether` with fixed MACs, brings up `usb0` at `192.168.15.244`, opens `usb0` in the stock iptables firewall, sets `preventScreenSaver` on powerd, and starts KOReader's dropbear (key-only). Then `devloop/host/run.sh [crate]` builds, copies to `/var/tmp`, runs and saves a framebuffer PNG; `ssh -F devloop/host/ssh_config kindle` for a shell. Auth uses a dedicated key, `$ARISTOTLE_CACHE/ssh/kindle_ed25519`. Stop, or a reboot, reverts everything.
- One-time host setup: `devloop/host/setup-host-net.sh` (NetworkManager profile matched by MAC, host `192.168.15.201`). Use `devloop/host/install-extensions.sh` whenever the device is in drive mode.
- Eject with `udisksctl unmount -b /dev/sda` only. `udisksctl power-off` removes the device from the USB bus, so the network gadget will not appear until a physical replug.
- Drive mode is one-shot. After ejecting on the host, the device leaves mass-storage mode while the cable stays in (the host sees a 0-byte `sda`), and only a replug re-enters it. While the userstore is exported, the device cannot write `/mnt/us`.
- Fallback without the network: copy a KUAL extension to `/mnt/us/extensions/<id>/` (`config.xml`, `menu.json`, `bin/*.sh`), eject, run it from KUAL (it runs as root), replug, and read the output from `/mnt/us`. `probe/device/aristotle-probe` is the template.
- Show status on screen with `eips` (stock) or FBInk (`/mnt/us/libkh/bin/fbink`).

## Device facts that break naive code

- **ABI.** Stock userspace is **softfp**: soft-float calling convention with VFPv3/NEON instructions, glibc 2.20, `/lib/ld-linux.so.3`, the koxtoolchain `kindlepw2` target. Hard-float *dynamic* binaries, including Plato's upstream `arm-unknown-linux-gnueabihf` build with `libmupdf.so`, will not run against the system libraries. Build **static `armv7-unknown-linux-musleabihf`**, which others report working on PW4 5.13.x. Use `armv7-unknown-linux-gnueabi` only if you must `dlopen` Amazon libraries such as `liblipc.so`.
- **Framebuffer.** It is not "width × height": visible 1072 × 1448, line length 1088 bytes, virtual height 6144, 8 bpp, `rotate=3`. Always use the stride from `FBIOGET_FSCREENINFO` and the offsets from `FBIOGET_VSCREENINFO` (both offsets are 0 on our unit; the "viewVertOrigin=4" that FBInk prints is its own view adjustment).
- **E-ink updates.** They use Lab126's own `MXCFB_SEND_UPDATE` struct and the *Zelda* waveform numbering (A2 = 6, GL16 = 3, REAGL = 4), not Kobo's or the PW2 one. Do not copy Plato's `mxcfb_sys.rs` structs blindly; use FBInk's Kindle headers as the ABI reference. Waveforms come from `/mnt/wfm/waveform_to_use/` and are chosen by temperature.
- **Page turns must be clean, not just fast.** Turn pages exactly like the stock reader: one **full-mode** update of the **whole screen** with waveform **mode 9**, and use mode 8 full for flash refreshes. Partial updates, and A2 previews followed by GL16, left visible ghosting in real reading. Short demos with near-identical pages hid it. Prerender the next page during the panel refresh. A tap turns on release (a hold selects text and never turns); the next page is prerendered, so the submit follows the release at once. Details: `docs/native-vs-aristotle.md`.
- **One update at a time.** The driver blocks `MXCFB_SEND_UPDATE` itself while an earlier update is still on the panel, whatever the regions. Never submit from an input loop: draw, then hand the damage to `aristotle_hal::display::Display`, whose thread coalesces everything drawn meanwhile into the next update. Deeper queues and per-tile updates were measured and are worse (`docs/eink-rendering.md`).
- **Measure, don't guess.** UI latency work uses record and replay: `aristotle-pen-live record=...` captures real input with kernel timestamps; `aristotle-pen-bench` replays it and reports event-to-panel latency percentiles. Keep one reference recording and compare every change against it (`docs/eink-rendering.md`).
- **Touch.** The chip varies per unit (Parade cyttsp5 or Goodix gt9xx, detected at boot), and the event node number varies too (an extra proximity sensor on LTE units). Find the device by name in `/proc/bus/input/devices`, never by a hard-coded `eventN`.
- **Users.** Stock daemons run as unprivileged users; for example `pillowd` runs as `framework`. Files you bind-mount over theirs must be readable by them. A root-only `umask 077` copy silently broke an earlier Pillow patch.
- **Taking the screen.** Per KOReader's practice (not yet verified by us), `powerd` keeps driving suspend and the screensaver after the GUI stops. `volumd` owns the USB export. Stop the GUI stack (`stop lab126_gui`) but keep or replace those two deliberately. See the KOReader notes in the reference.
- **Kernel and boot.** Modules are unsigned, so our own `.ko` files load if the vermagic matches `4.1.15-lab126`. The PW4 is reported **secure-boot locked** (U-Boot: `secure_cpu: 1, production: 1, unlocked: 0`; fastboot flash is blocked). eMMC access goes through Lab126's "Falcon" layer. So "own kernel" means kexec from the running stock kernel, tried first in the QEMU PW4 emulator (`katadelos/eink-emulator`). Treat the boot partitions, diags and IDME as read-only.
- **Related projects.** Read `docs/related-projects.md` before building anything that might already exist. Display-ABI Rust code is in `slint-kindle-backend`, a reversible takeover pattern in `yb-reader`, a QEMU PW4 machine in `eink-emulator`, and the maintained Plato fork is `cadmus`.

## Workflow

- Static questions: answer them from the firmware image in `$ARISTOTLE_CACHE/probe/static/` before touching the device.
- Runtime questions: extend `probe/device/aristotle-probe/bin/probe.sh`. It must stay read-only outside its output directory. Copy results into `$ARISTOTLE_CACHE/probe/device/` and record durable findings in `docs/pw4-reference.md`.
- For Plato: its engine is consumed through `crates/aristotle-render`, which builds `plato-core` from the fork in `third_party/plato` (`docs/reader.md`, "How Plato is consumed"). PDF and the other non-EPUB formats go through MuPDF (`mupdf_wrapper`).
